# AI 项目托管平台开发计划

> 本文是最初的独立 PaaS 方案，已被 Coolify 集成方向取代。当前目标架构、源码包部署流程和迁移状态以 [Coolify 集成方案](coolify-integration.md) 与 [开发计划](development-plan.md) 为准。下文仅作历史参考。

## 概要
从空工作区构建一个面向公司内网的 AI 项目托管平台。开发者通过 AIHub 中的 Skill 和 CLI 上传本地项目；平台做部署前检查、自动识别构建、运行 Web 服务或后台 Worker，并提供内部访问地址。管理员可以管理用户、项目、部署、日志与宿主机资源。

首期以**单台 Linux Docker 宿主机**为目标，验证 100+ 轻量实例的管理与运行能力；架构保留后续增加节点的边界，但首期不实现跨节点调度。项目源码不要求 Dockerfile，构建采用 Cloud Native Buildpacks：它可以识别源码并产出 OCI 镜像，也支持为同一镜像声明不同运行进程。([buildpacks.io](https://buildpacks.io/how-it-works/?utm_source=openai))

## 实施变更
- **平台与组件**
  - 后端和 CLI 使用 Go；管理员界面使用 React + TypeScript；PostgreSQL 保存用户、项目、部署、配额和审计记录。
  - 用 Go Worker 执行构建和部署任务，以 PostgreSQL 任务表承载首期队列，避免首期额外引入消息队列。
  - Docker Engine 负责运行容器；Traefik 负责内部域名路由和 HTTPS；Prometheus、cAdvisor、node_exporter 采集容器与宿主机指标。
  - 提供 Docker Compose 部署包，包含平台控制面及其依赖；业务容器由控制面通过受限的节点执行组件管理。

- **开发者提交与 Skill**
  - 提供平台 Skill 和 `platform` CLI，覆盖初始化配置、部署、查看状态、读取构建/运行日志和查看访问地址。
  - `platform deploy` 将工作区打包上传。排除 `.git`、依赖目录、`.env` 和默认敏感文件；支持 `.platformignore`。环境变量与密钥通过单独的 API 配置，不进入源码包。
  - CLI 在本地运行快速检查；平台端再次执行可信的服务端检查，结果、错误和建议可回传给 Agent。
  - Skill 生成或维护简短的 `platform.yaml`，声明服务角色、端口或 Worker 启动命令、健康检查和资源档位；语言与框架仍由构建器自动识别。
  - 首期仅支持 Node.js 与 Python；检测不支持或存在歧义时明确失败并给出修复建议，不静默猜测。

- **部署与运行生命周期**
  - 一次部署创建不可变版本记录；平台依次执行上传校验、源码检查、Buildpacks 构建、镜像标记、容器更新、健康检查和流量切换。
  - 一个项目版本允许定义一个 Web 角色及可选的 Worker 角色，默认共用构建镜像、配置和版本号；Worker 不暴露公网/内网 HTTP 路由。
  - 仅健康检查通过后才标记部署成功；构建失败或新版本健康检查失败时保留当前运行版本，并提供回滚操作。
  - Web 服务分配内部域名；反向代理只转发到健康实例。配置变化创建新部署版本，密钥在 UI 中不回显。
  - 持久化数据仅作为 Demo 用：每项目提供受限持久卷，默认 1 GiB、管理员可调整；达到 80% 告警、达到上限时阻止继续写入并提示迁移正式存储。宿主机需使用支持项目配额的文件系统；不提供托管数据库。
  - 默认 CPU/内存/进程数限制采用可配置资源档位，创建实例前检查宿主机可用容量；禁止特权容器、host 网络、任意宿主机挂载和不必要 Linux capabilities。

- **认证、API 与管理界面**
  - 管理员邀请开发者；关闭自助注册。角色首期为 `admin` 和 `developer`。开发者只能管理自己的项目和部署，管理员可查看、停止、重启、删除任意实例并管理用户和配额。
  - 后端提供版本化 REST API，并以 OpenAPI 描述。核心接口包括：登录/退出、创建和查询项目、创建部署、查询部署状态、分页读取构建/运行日志、配置项目环境变量、查看资源指标、管理员管理用户/实例/节点。
  - 每个部署操作记录操作者、项目、版本、动作、时间和结果；认证失败、构建失败、容器反复重启和资源告警进入审计/告警视图。
  - 管理后台提供服务列表与筛选、部署详情、日志查看、版本回滚、用户管理、宿主机 CPU/内存/磁盘与容量概览、项目资源占用和持久卷用量。

- **测试与验收**
  - 单元测试覆盖清单解析、源码包过滤、技术栈识别、权限、配额和部署状态转换。
  - 集成测试覆盖 Node/Python 构建、Web/Worker 启动、健康检查、日志、密钥注入、失败回滚、停止/重启/删除及持久卷配额。
  - 安全测试覆盖未授权访问、越权操作、源码包中的敏感文件拦截、容器特权/宿主机挂载拒绝及构建资源限制。
  - 前端测试覆盖管理员和开发者权限视图、空状态、失败态、长日志与资源数据刷新。
  - 验收时在约定参考宿主机上运行 20 个轻量测试实例，验证实例列表、状态、日志、资源统计和批量管理可用；不在未明确硬件规格前承诺生产负载 SLA。

- **阶段顺序**
  1. 定义部署清单、API、状态机、资源档位和安全边界；完成 Skill/CLI 与服务端契约。
  2. 完成登录、用户/项目管理、源码上传、检查反馈和 Node/Python 构建。
  3. 完成 Docker 部署生命周期、内部域名、健康检查、日志和版本回滚。
  4. 完成管理员资源面板、告警、审计、持久卷配额及 20 实例验收。
  5. 补齐安装文档、宿主机初始化脚本、备份恢复与升级说明。

## 假设与默认值
- 平台运行于公司内网，目标环境提供内部 DNS 通配解析和可配置 TLS 证书；不开放公网访问。
- 首期账号由管理员邀请，不接入公司 SSO；后续可增加 OIDC。
- 首期只接受自动识别的 Node.js/Python 项目；不允许用户自带 Dockerfile 或任意构建脚本，以收敛构建控制面暴露面。
- 自动检查与构建成功即可部署，不设置逐次人工审批；管理员可随时停止或删除实例。
- “100+”指首期管理和压测目标，不等同于固定业务容量；实际可运行数量由宿主机规格、应用负载和配置配额决定。
- 1 GiB 持久卷及 80% 告警为首发默认值，管理员可调整；超限硬约束依赖宿主机文件系统配额能力。
